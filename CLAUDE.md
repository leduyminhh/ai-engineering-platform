# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

@AGENTS.md

## What this is

`ai-engineering-platform` (CLI: `aip`) projects **canonical AI-agent capability content** into **provider-native files** for Codex, Claude Code, Cursor, and Google Antigravity. You author capabilities once under `plugins/` and `core/`; the CLI generates the per-provider skills, marketplace, rules, and workflow docs into a target project, and `aip init` writes an "AI Engineering" baseline block into that project's `AGENTS.md` (`CLAUDE.md` imports it).

There is no application runtime to start — the deliverable is the CLI and the content it projects. Pure ESM, **zero runtime dependencies**, no build step.

## Commands

Node.js 20+ required.

```bash
npm test            # validate --build + install + wizard + managed-block + init + pack-guard + args + transcript-stats + transcript-usage + statusline + status + route tests (CI: matrix ubuntu/windows × Node 20/24 + claude plugin validate --strict)
npm run build       # node cli/build.mjs --target all   -> build/<provider>/
npm run list        # list discovered adapters + plugins
npm run validate    # node test/validate.mjs (source + build-output contract)
npm run overlap     # node test/overlap.mjs (skill/workflow overlap report, advisory)
node scripts/routing-score.mjs [--lock]   # điểm routing rank-1 trên description (npm test kiểm ngưỡng ở test/routing/rank1.lock.json; --lock chỉ nâng)
node scripts/ledger-metrics.mjs --project <dir> [--label <nhãn>] [--anon]   # --anon: thay tên request bằng r1..rN; đếm vòng review, ruling, minor từ .aip/runs/**/progress.md (in JSON; số nền ở docs/requests/2026-11-11-skill-enrichment-from-usage/baseline.json)
npm run pack:verify # pack-guard: assert the npm-publish file set stays within policy
node scripts/eval-run.mjs --plugin <id> --max-cost-usd <usd> [--runs 3] [--scaffold] [--case <glob>]   # chạy eval thật (tốn tiền model, không nằm trong npm test)
```

Version gate: Claude Code caches plugins **by version**, so any change to projected content must bump the
plugin's `.manifest.json` version (core: `core/.manifest.json`). After `npm run build`, run
`node cli/lib/versions.mjs --lock` to refresh `plugins/_versions.lock.json` (it refuses when content changed but
the version did not); `npm test` fails if the lock does not match the build. `aip check` reports installed
Claude plugins whose version differs from source.

Run a **single test file** directly (no build step):

```bash
node test/validate.mjs --build
node test/validate.mjs --only <substr>   # chạy một nhóm module (contract/content), vd --only versions
node test/install.test.mjs
```

Tests that exercise install/uninstall read from `build/`; if validate fails with a missing `SKILL.md`, rebuild first (`npm run build`).

End-user `aip` commands (run inside a *target* project after `npm link`): `node cli/index.mjs --help`.

Every command runs `node cli/index.mjs` — no tsc/dist. `node cli/dist.mjs [--dry-run]` is separate: it builds a local `dist` git branch holding `build/claude` (minus `drafts/`) for `claude plugin marketplace add <owner>/<repo>@dist`; it never pushes and needs git >= 2.42 (`git worktree add --orphan`).

## Architecture

### Build/runtime mix
Pure ESM, zero runtime dependencies (Node built-ins only, incl. a hand-rolled YAML-frontmatter parser and ZIP writer). `cli/index.mjs` is the entry point (arg parse + routing + wizard gate). Logic lives in `cli/lib/*.mjs` and `cli/build.mjs`. The `bin` entries (`aip`, `ai-engineering-platform`) and all tests run directly from source.

### The projection pipeline (the core idea)
Content flows one direction: **canonical source → in-memory model → adapter → files on disk.**

1. **Canonical source** — `plugins/<id>/` (`.manifest.json` = `{id,name,description,version}` + `shared/principles.md` + `skills/<skill-id>/SKILL.md` + `agents/<agent-id>.md`), plus `plugins/_marketplace.json` (marketplace identity) and `plugins/_cowork.json` (the skill set zipped for Anthropic Cowork upload). Shared content lives in `core/` (`.manifest.json`, `agents/AGENTS.template.md`, `principles/`, `skills/git-workflow/`, `skills/git-release/`, `skills/plan-execution/` (task-loop protocol, 3 Node scripts plus the shared `workspace.mjs` that resolves `<main repo root>/.aip/runs/<request>/<part>/`, and `autonomy.mjs` that prints the effective `autonomy` key), `skills/using-aip/`, `skills/git-worktree/`, `skills/aip-status/` (`aip status` progress page: JSON/HTML model + action widget), `skills/brainstorming/` (brainstorm into a routed `brief.md`: 4 references with `clarify-core.md` as the single source of the shared clarify step, plus `scripts/route.mjs` deterministic router), `permissions/policy.json` (standard permission groups; `cli/lib/permissions.mjs` builds the `permissions` block that `aip init --full` writes to `.claude/settings.json` only when absent), `skills/artifact-templates/` — 13 artifact templates under `references/`, incl. `spec` for living specs in `docs/specs/<capability>/spec.md` and `specs-readme` for its entry point `docs/specs/README.md`; `scripts/check-request.mjs` warns W1–W23 (W15/W16 request status, W17/W18 plan task `**Kind:**`, W19/W20 request parts, W21 task `**TDD:**`, W22 `calc:` blocks in AC, W23 a design saying "Không ảnh hưởng" while the repo has no `docs/specs/<capability>/spec.md` yet), W10–W14 checking the design's `## Ảnh hưởng spec` against those specs (W10 only for request folders named `<yyyy-mm-dd>-<slug>` dated 2026-10-21 or later; older or undated folders are skipped), W13 only with `--base <ref>`; `scripts/check-partition.mjs` warns P1 (overlapping files), P4 (consumed interface) and P5 (Consumes/Produces content with no backticked name, which P4 cannot check) between the parts of one `Song song` group in `## Bảng part`, P2 for any part with a group label that writes a forbidden shared file (parts with status `bỏ` are skipped), and P3 for a task-level `**Song song:**` (removed), advisory only). Cross-plugin workflows live in the repo-level `workflows/` (`<slug>/WORKFLOW.md`, `orchestrator/WORKFLOW.md`, registry table in the orchestrator body) plus the workflow template at `core/skills/artifact-templates/references/workflow.template.md`. Project scaffolding lives in `templates/init/` (`templates/ci/` holds a CI workflow example that ships in the npm package but `aip init` never copies); the skill template lives at `core/skills/artifact-templates/references/skill.template.md`.
   **Hooks** — `core/hooks/hooks.json` + `core/hooks/scripts/guard-bash.mjs` / `guard-files.mjs` / `guard-mcp.mjs` (PreToolUse; `guard-mcp` matcher `mcp__.*`) and `gate-stop.mjs` (Stop/SubagentStop; blocks once when the turn edited code without running a test/lint/build afterwards) and `session-start.mjs` (SessionStart; injects a ≤ 1200-char skill-first rule that points at the `using-aip` skill (off with `bootstrapInject: false`), the newest fresh `handoff.md` and the plan ledger `.aip/runs/*/*/progress.md` (main repo root and worktree root; legacy `docs/requests/*/.sdd/progress.md` only for a request with no `.aip` run) (≤ 2000 chars, skipped when it has a `Plan: complete` or `Part: complete` line or is older than `handoffMaxAgeHours`) on startup/clear/compact, sharing one 9000-char budget, warns on a cold resume/fork — never blocks) — zero-dep Node, fail-open on internal errors, no file writes, only `git rev-parse` and `git ls-files` reads. All five read `<git-root>/.claude/aip-gate.json` through `gate-config.mjs` (worktree root, then main repo root): `stopGate`/`testCommands`/`exemptAgents` for the Stop gate, `allowEnvFiles` to stop guarding env files (keys/credentials stay guarded; `stopGate`, `exemptAgents` and `allowEnvFiles` count only from a file git does not track, see `GATE_KEYS` in `gate-file.mjs`), `mcpAllow`/`mcpDeny` (string arrays of MCP server names for `guard-mcp`; `deny` wins, absent = no change), `mode` (`"ask"` default | `"full"`; `full` is effective only with session `permission_mode` `bypassPermissions` and a file not tracked by git: the guards drop H2/H3/`mcpAllow`, keep H1 per `fullKeep` (default `["push"]`) and H5, and confine writes to the project root, `scratchpad_dir` and `fullRoots` (absolute paths; `fullReadRoots` adds read-only roots); set with `aip mode`), `autonomy` (`{mergeLocal, cleanup, partRunner, planRunner}`; `partRunner`/`planRunner` only order the options of the execution-mode question and `autonomy.mjs --set` saves them; read by `plan-execution`'s `autonomy.mjs`, not by any hook; set with `aip autonomy`, logic in `cli/lib/autonomy.mjs`), `bootstrapInject`/`handoffInject`/`ledgerInject`/`resumeWarn` (default on; `false` disables) plus `handoffPath` (only a `.md` file inside the session cwd, also after symlinks)/`handoffMaxAgeHours` (default 24; also the ledger age limit) for the SessionStart hook. The Claude adapter copies `hooks/` into the plugin and generates `hooks/scope-lock.json` from the agent key `writeScope`. Hooks exist **only in plugin mode** (skills-mode never installs them). A plugin gets hooks by shipping `hooks/hooks.json`.
   **Parallel agents** — the convention for several agents at once lives in skill `git-worktree`, `references/parallel-agents.md` (README section `## Hooks`): one Claude Code worktree per part (parallel only between parts, never inside a part), branch `worktree-<slug>-p<nn>` in `.claude/worktrees/<slug>-p<nn>/`, disjoint file sets checked by `check-partition.mjs`, merged `--no-ff` into the integration branch. aip does not run agents; only `writeScope` + `guard-files` enforce write scope, and the hooks resolve `aip-gate.json` from the worktree root, then the main repo root.
   **Evals** — `evals/<plugin>/<case>/` (`prompt.md` + `graders/*.md`, optional `case.yaml`/`scaffold.sh`) are repo-level and not shipped; `test/contract/95-evals.contract.mjs` checks structure only. Running `claude plugin eval` costs model usage and is manual (see `evals/README.md`).
2. **`cli/lib/plugins.mjs`** — `loadPlugins()` scans `plugins/*/.manifest.json` (dirs starting `_` are config, not plugins); `loadSkills()` discovers `skills/*/SKILL.md`, parses frontmatter with a zero-dep parser, and orders by `order`. `loadAgents()` discovers `agents/*.md` per plugin (frontmatter `name`, `description`, `mode`, `skills`). `loadCore()` returns core as a plugin-shaped object (identity/version from `core/.manifest.json`). `loadWorkflows()` returns `workflows/` as a plugin-shaped object (`{ id: 'workflows', name, version, description, stages: [...], agents: [] }`), one stage per `WORKFLOW.md` parsed with the same frontmatter parser plus `kind`, `tier`, `risk`, `agents[]`, `requires[]`, and `graph` (parsed `graph.json` via `readGraph`, or `null`). The skill is the unit; frontmatter (`order`, `title`, `runsIn`, `invoke`, `sharedAssets`) describes each one — **this repo runs skills as standalone recipes** (no mandatory chain).
3. **`cli/build.mjs`** — `discoverAdapters()` scans `adapters/*/adapter.mjs` (auto-discovered by convention; `_`-prefixed dirs skipped). Cross-adapter helpers (skill/agent/workflow rendering, Codex TOML) live in `adapters/_shared/lib.mjs` + `agents.mjs`; workflow body/registry parsing and dependency expansion live in `cli/lib/workflows.mjs`. Each adapter is a pure function `build(plugins, { outDir, marketplace, core }) -> fileEntry[]`, where an entry is `{path, content}` | `{path, copyFrom}` | `{path, copyDir}`. `cli/lib/write.mjs` `writeFiles()` is the sole materializer.
4. **`cli/lib/install.mjs`** — `install()` / `uninstall()` / `check()` / `update()` apply the built output to the target project: symlink-first with copy fallback (junctions on Windows; copy when run from `node_modules`), child-by-child directory merge that never clobbers user files, and additive installs. Everything is recorded in `<scope-root>/.ai-engineering/manifest.json`. On Windows, never `rm -rf` a sandbox containing junctions from Git Bash (it deletes through into `build/`); clean up with Node `fs.rmSync`.

### State and ownership
All managed state lives in a single flat file: `<scope-root>/.ai-engineering/manifest.json` (per-install `files[]`, `links[]`, and legacy `managed[]`). `install.mjs` uses it to remove only tracked paths on uninstall (never link targets) and prune emptied directories. Install writes no instruction file; a legacy `managed[]` entry from an older version is cleaned only at global scope (`~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`), when its entry is replaced or removed, or on the plugin-refresh branch of `update`. The baseline block is written by `aip init` (`cli/lib/init.mjs`) into the project's `AGENTS.md`: `cli/lib/managed-block.mjs` rewrites only the region between its markers (source region = `core/agents/AGENTS.template.md`), leaving everything outside the markers untouched.

### Scope
Every lifecycle command takes a scope: **project** (default, cwd) or **global** (`-g` / `--scope global`, home dir). `$AIE_INSTALL_ROOT` overrides the scope root (used by tests to isolate installs). `install` supports `claude`, `cursor`, `codex` (Codex skills go to `<root>/.agents/skills/`, agent TOML to `<root>/.codex/agents/`; reinstall removes a legacy `.codex/skills` install via the manifest; the installer never overwrites or deletes a foreign regular file when placing skills, merges into a foreign real directory keeping its existing files (skipped with a warning), and skips a foreign symlink/junction at the destination with a warning; only links recorded in the manifest or already pointing at the source are replaced); `antigravity` **builds** but is not installed by default (installable via explicit `--provider antigravity`). Workflows are installed only for `claude` and `codex` (`WORKFLOW_PROVIDERS` in `cli/lib/workflows.mjs`); cursor/antigravity have no native workflow target. No provider's install writes the baseline block (cursor/antigravity governance is already inlined). Legacy cleanup at global scope skips an instruction file that is a symlink/junction.

### Interactive wizard
`cli/lib/wizard.mjs` is a step-machine with back-navigation and injectable deps; zero-dep TUI primitives (`selectOne`, `selectMany`, `confirmStep`) live in `cli/lib/prompt.mjs`. Step logic is separated from terminal I/O so it is unit-testable without a TTY. `cli/index.mjs` routes to the wizard when stdin is a TTY and no explicit flags are given, else to non-interactive execution. Flag parsing lives in `cli/lib/args.mjs`; `--skill` defaults to `[]` (meaning "no skill filter", not an empty selection), so install/uninstall changes should be tested through the `parse()` output, not hand-built args. `--all` does not set `explicit`; it only makes the wizard build its skill tree from `skillCatalog()` (drafts labelled `(draft)`) instead of `offeredCatalog()`.

### npm packaging guard
`cli/lib/pack-guard.mjs` + `pack.config.json` verify (on `prepack`) that the npm-publish file set stays within an allowlist (fail-loud). The npm package ships **core only**: any `plugins/<id>/` not listed in `pack.config.json` `shipPlugins` (empty) and all of `workflows/` are rejected, and a plugin listed in `shipPlugins` must be present. `plugins/_published.json` gates what the wizard offers from source and what the Claude marketplace lists: draft skills (and agents using them) build to `build/claude/drafts/<plugin>/…` (skills-mode install still reads them; plugin-mode install does not — it warns about dropped draft skills) and `node cli/build.mjs --include-draft` restores the single-tree layout; users install plugins/workflows from source (`npm link`). This is separate from `cli/lib/pack.mjs`, a zero-dep deterministic ZIP packer that bundles the `_cowork.json` skill set for Anthropic Cowork upload.

### Adding capability content
Checklist for a new skill, agent, workflow or provider behavior (frontmatter rules, conventions, version bump): project skill `aip-add-content` (`.claude/skills/aip-add-content/SKILL.md`).

## Conventions

- The repository-wide agent execution baseline (read-before-write, surgical changes, fail-loud, verification contract) is defined in [AGENTS.md](AGENTS.md) — kept byte-identical to `core/agents/AGENTS.template.md` — and applies here.
- **Language:** user-facing repository work is written in Vietnamese (proper UTF-8 with diacritics). Docs ship as paired `README.md` / `README_VI.md`; skill content is Vietnamese.
- Source files are UTF-8 **without BOM**, LF line endings.
- Content spans `core` (principles + `git-workflow`, `git-release`, `artifact-templates`, `plan-execution` (task-loop protocol with 3 Node scripts `task-brief`/`review-package`/`ledger` sharing `workspace.mjs`), `using-aip` (skill-first bootstrap injected by `session-start`), `git-worktree`, `aip-status` (`aip status` + action widget), `brainstorming` (brief + routing), 8 skills) and 5 plugins under `plugins/`: `backend` (10 skills published incl. `backend-fix`, `backend-performance`, gated per-skill in `plugins/_published.json`), `frontend` (10 skills published incl. `frontend-fix`, `frontend-data-integration`, `frontend-e2e-testing`, `frontend-performance`, gated per-skill in `plugins/_published.json`), `engineering` (13 skills, incl. `engineering-writing-style`, `engineering-spec-backfill`, `engineering-plan-writing`, `engineering-repo-audit`, `engineering-tdd`, `engineering-debugging`), `ops` (3 skills) are **published** (offered by the wizard when run from source; not shipped in the npm package, which is core only); `data` is **partly published** (`data-db-migration` published — gated per-skill in `plugins/_published.json` and offered by the wizard; the 4 `data-oltp-*`/`data-olap-*` skills stay **draft**: build/validate and install via explicit `--plugin`/`--skill` or `aip --all` (skills mode only), not offered by default). Cross-plugin **workflows + the orchestrator** live in the repo-level `workflows/` (4 pipeline workflows; a capability-only task belongs in a skill, which the orchestrator routes to); domain **agents** live in `plugins/<id>/agents/`. There is no mandatory pipeline; every skill and workflow is invoked on demand.

## Workflow defaults

Spec/design approval and plan approval stay human gates; these defaults remove only the prompts after them.

- Route by request: a feature → `workflow-feature`; a bugfix → `workflow-bugfix`. Execute an approved plan with skill `plan-execution`; it asks how to run (subagent per task or inline) before each execution and remembers the answer as a suggestion.
- Work on a `feature/<slug>` branch and commit each task through `core:git-workflow` without pausing (AGENTS.md Safety).
- Specs and plans go to `docs/requests/<yyyy-mm-dd>-<slug>/` (`design.md`, `plan.md`); the ledger is `.aip/runs/<request>/<part>/progress.md` at the main repo root (git-ignored).
- Before finishing: `npm test`; if projected content changed, bump the owning `.manifest.json` version and run `node cli/lib/versions.mjs --lock`.
- Finishing the branch: default to "Keep the branch as-is"; merge or push only after the human confirms.
