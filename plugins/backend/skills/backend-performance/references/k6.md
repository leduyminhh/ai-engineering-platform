# k6 — load test HTTP API cho chế độ `measure`

Tài liệu tham chiếu cho `backend-performance`, chế độ `measure`. Mọi lệnh, cờ và tên API k6 trong file này
chưa được đối chiếu với tài liệu chính thức của phiên bản project đang dùng → gắn `[Unverified]`; kiểm lại với
output `k6 version` `[Unverified]` và tài liệu của đúng phiên bản trước khi dựa vào.

## Khi nào dùng k6

- Đo latency/throughput/error rate của **HTTP API** dưới tải (một endpoint hoặc một luồng nhiều request).
- Không dùng cho hàm/thuật toán nóng trong process → dùng micro-benchmark (`jmh-pytest-benchmark.md`).
- Project đã có công cụ tải khác (JMeter, Gatling, Locust) → **dùng công cụ đó**, giữ nguyên tắc bảng điều kiện.
- Chưa có k6 trên máy/CI: cài đặt là thay đổi tool → **hỏi trước**, không tự cài.

## Cách tách warm-up: hai lần chạy riêng

Summary cuối bài test của k6 tính trên **toàn bộ** lần chạy, gồm cả ramp-up/ramp-down nếu có. Vì vậy recipe này
dùng MỘT cách duy nhất:

1. **Lần warm-up** (`PHASE=warmup`): chạy ngắn, cùng script, cùng tải; **bỏ toàn bộ kết quả**, không ghi file
   summary, không đọc số.
2. **Lần đo** (`PHASE=measure`): tải **hằng định, không ramp** (`vus` + `duration`) → mọi số trong summary thuộc
   pha đo. Số báo cáo **chỉ đọc từ lần đo**.

Warm-up chạy ngay trước lần đo, trên cùng process ứng dụng. Ứng dụng khởi động lại giữa các lần đo → warm-up lại.
Ghi cách làm này vào hàng Warm-up của bảng điều kiện.

## Script mẫu `perf/<luồng>.js`

Cú pháp dưới đây theo API k6 phổ biến `[Unverified]`. Số VU, thời lượng là **giá trị mẫu của mô hình tải**,
không phải số đo; thay bằng giá trị trong bảng điều kiện (`measure-conditions.md`).

```js
import http from 'k6/http';
import { check, sleep } from 'k6';

// Host chỉ lấy từ biến môi trường; mặc định local. Không bao giờ hard-code host staging/production.
const BASE_URL = __ENV.BASE_URL || 'http://localhost:8080';
const PHASE = __ENV.PHASE || 'measure';
// Mục tiêu p95 lấy từ Bước 1 (metric & mục tiêu); không tự đặt số.
const P95_TARGET_MS = __ENV.P95_TARGET_MS;
// Mặc định không có think time để throughput không bị chặn bởi sleep (xem mục Throughput).
const THINK_TIME_S = Number(__ENV.THINK_TIME_S || 0);
const API_TOKEN = __ENV.API_TOKEN;
if (!API_TOKEN) {
  // Dừng sớm thay vì gửi "Bearer undefined" rồi đo toàn 401.
  throw new Error('Thiếu biến môi trường API_TOKEN (token tài khoản test)');
}

export const options = {
  vus: Number(__ENV.VUS || 10), // tải hằng định, không ramp (giá trị mẫu)
  duration: PHASE === 'warmup' ? __ENV.WARMUP_DURATION || '30s' : __ENV.DURATION || '2m', // giá trị mẫu
  summaryTrendStats: ['avg', 'min', 'med', 'max', 'p(90)', 'p(95)', 'p(99)'],
  thresholds: PHASE === 'measure' && P95_TARGET_MS ? { http_req_duration: [`p(95)<${P95_TARGET_MS}`] } : {},
};

export default function () {
  const res = http.get(`${BASE_URL}/api/orders?page=0`, {
    headers: { Authorization: `Bearer ${API_TOKEN}` },
  });
  check(res, { 'status 200': (r) => r.status === 200 });
  if (THINK_TIME_S > 0) sleep(THINK_TIME_S);
}
```

`[Unverified]`: `throw` ở init context làm k6 dừng trước khi gửi request; thứ tự và tên trong
`summaryTrendStats`; `options.duration` nhận biểu thức theo `__ENV`.

## Lệnh chạy mẫu

```bash
# [Unverified] cờ -e và --summary-export; kiểm lại theo phiên bản k6 thật
# 1) warm-up: bỏ kết quả
k6 run -e PHASE=warmup -e BASE_URL=http://localhost:8080 perf/<luồng>.js
# 2) lần đo: chỉ đọc số từ đây; lặp run1..run3 (warm-up lại nếu ứng dụng khởi động lại)
k6 run -e PHASE=measure -e BASE_URL=http://localhost:8080 -e P95_TARGET_MS="$P95_TARGET_MS" \
  --summary-export=perf/out/<luồng>-run1.json perf/<luồng>.js
```

- Trend stats mặc định của k6 đã có `med` (p50), `p(90)`, `p(95)` `[Unverified]`; **chỉ p99** cần cấu hình thêm
  qua `summaryTrendStats` trong `options` (như mẫu) hoặc cờ `--summary-trend-stats` `[Unverified]`.
- Có thể xuất summary tuỳ biến bằng hàm `handleSummary(data)` trong script `[Unverified]`.
- Thư mục output (`perf/out/`) là artifact đo; hỏi người dùng có muốn commit hay thêm vào `.gitignore`.

## Throughput và think time

- Mô hình đóng (`vus` cố định) có `sleep(1)` giới hạn throughput ở khoảng số VU request/giây — số đó phản ánh
  think time chứ không phản ánh năng lực hệ thống, nên không dùng để so throughput trước/sau.
- So throughput: để `THINK_TIME_S=0` (mặc định mẫu), hoặc dùng mô hình mở theo RPS với executor kiểu
  arrival-rate (ví dụ `constant-arrival-rate`) `[Unverified]`.
- Chỉ giữ think time khi mục tiêu là mô phỏng hành vi người dùng; ghi rõ vào hàng Mô hình tải.

## Lấy số từ summary (chỉ lần đo)

- **p50/p95/p99:** từ metric `http_req_duration` (trend; p50 = `med`) `[Unverified]` tên metric theo phiên bản.
- **Throughput:** từ metric `http_reqs` (rate, req/s) `[Unverified]`.
- **Error rate:** từ metric `http_req_failed` (rate) `[Unverified]` — mặc định tính response ngoài dải 200–399,
  tức cả 4xx lẫn 5xx, cộng lỗi mạng/timeout `[Unverified]`. Đây là định nghĩa bảng kết quả dùng
  (`measure-conditions.md`); tỉ lệ `check` fail báo riêng.
- Chạy **≥ 3 lần đo** với cùng lệnh; mỗi lần một file summary (`run1`, `run2`, `run3`); tính độ lệch p95 theo
  `measure-conditions.md`. Ghi nguyên văn lệnh (cả lệnh warm-up) vào báo cáo.

## Cảnh báo an toàn

- **Không** trỏ `BASE_URL` vào staging/production (P1). Host không phải local/test → từ chối, báo.
- Credential/token chỉ qua biến môi trường (`API_TOKEN`), dùng tài khoản test; không in giá trị ra log hay
  báo cáo — chỉ nêu tên biến.
- Máy sinh tải cũng tốn CPU: chạy k6 và ứng dụng trên cùng máy yếu làm số lệch → ghi vào residual risk.
