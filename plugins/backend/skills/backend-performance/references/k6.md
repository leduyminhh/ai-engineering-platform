# k6 — load test HTTP API cho chế độ `measure`

Tài liệu tham chiếu cho `backend-performance`, chế độ `measure`. Mọi lệnh, cờ và tên API k6 trong file này
chưa được đối chiếu với tài liệu chính thức của phiên bản project đang dùng → gắn `[Unverified]`; kiểm lại với
output `k6 version` `[Unverified]` và tài liệu của đúng phiên bản trước khi dựa vào.

## Khi nào dùng k6

- Đo latency/throughput/error rate của **HTTP API** dưới tải (một endpoint hoặc một luồng nhiều request).
- Không dùng cho hàm/thuật toán nóng trong process → dùng micro-benchmark (`jmh-pytest-benchmark.md`).
- Project đã có công cụ tải khác (JMeter, Gatling, Locust) → **dùng công cụ đó**, giữ nguyên tắc bảng điều kiện.
- Chưa có k6 trên máy/CI: cài đặt là thay đổi tool → **hỏi trước**, không tự cài.

## Script mẫu `perf/<luồng>.js`

Cú pháp dưới đây theo API k6 phổ biến `[Unverified]`. Số VU, thời lượng là **giá trị mẫu của mô hình tải**,
không phải số đo; thay bằng giá trị trong bảng điều kiện (`measure-conditions.md`).

```js
import http from 'k6/http';
import { check, sleep } from 'k6';

// Host chỉ lấy từ biến môi trường; mặc định local. Không bao giờ hard-code host staging/production.
const BASE_URL = __ENV.BASE_URL || 'http://localhost:8080';
// Mục tiêu p95 lấy từ Bước 1 (metric & mục tiêu); không tự đặt số.
const P95_TARGET_MS = __ENV.P95_TARGET_MS;

export const options = {
  stages: [
    { duration: '30s', target: 10 }, // ramp-up (giá trị mẫu)
    { duration: '2m', target: 10 },  // pha đo (giá trị mẫu)
    { duration: '15s', target: 0 },  // ramp-down
  ],
  thresholds: P95_TARGET_MS ? { http_req_duration: [`p(95)<${P95_TARGET_MS}`] } : {},
};

export default function () {
  const res = http.get(`${BASE_URL}/api/orders?page=0`, {
    headers: { Authorization: `Bearer ${__ENV.API_TOKEN}` }, // token test, truyền qua biến môi trường
  });
  check(res, { 'status 200': (r) => r.status === 200 });
  sleep(1);
}
```

Thay cho `stages`, mô hình đóng đơn giản dùng `vus` + `duration` `[Unverified]`; mô hình mở theo RPS dùng
scenario executor kiểu arrival-rate `[Unverified]`. Ghi loại mô hình vào bảng điều kiện.

Warm-up: chạy một lần ngắn riêng trước pha đo, hoặc tách scenario warm-up và chỉ đọc số của pha đo
`[Unverified]` (cách lọc số theo scenario/tag tuỳ phiên bản k6).

## Lệnh chạy mẫu

```bash
# [Unverified] cờ -e và --summary-export; kiểm lại theo phiên bản k6 thật
k6 run -e BASE_URL=http://localhost:8080 -e P95_TARGET_MS="$P95_TARGET_MS" perf/<luồng>.js
k6 run -e BASE_URL=http://localhost:8080 --summary-export=perf/out/<luồng>-run1.json perf/<luồng>.js
```

- Để summary có p50/p99 ngoài mặc định, cấu hình trend stats (ví dụ `--summary-trend-stats` hoặc
  `summaryTrendStats` trong `options`) `[Unverified]`.
- Có thể xuất summary tuỳ biến bằng hàm `handleSummary(data)` trong script `[Unverified]`.
- Thư mục output (`perf/out/`) là artifact đo; hỏi người dùng có muốn commit hay thêm vào `.gitignore`.

## Lấy số từ summary

- **p50/p95/p99:** từ metric `http_req_duration` (trend) `[Unverified]` tên metric theo phiên bản.
- **Throughput:** từ metric `http_reqs` (rate, req/s) `[Unverified]`.
- **Error rate:** từ metric `http_req_failed` (rate) `[Unverified]`, đối chiếu thêm tỉ lệ `check` fail.
- Chạy **≥ 3 lần** với cùng lệnh; mỗi lần một file summary (`run1`, `run2`, `run3`); tính độ lệch p95 theo
  `measure-conditions.md`. Ghi nguyên văn lệnh vào báo cáo.

## Cảnh báo an toàn

- **Không** trỏ `BASE_URL` vào staging/production (P1). Host không phải local/test → từ chối, báo.
- Credential/token chỉ qua biến môi trường (`API_TOKEN`), dùng tài khoản test; không in giá trị ra log hay
  báo cáo — chỉ nêu tên biến.
- Máy sinh tải cũng tốn CPU: chạy k6 và ứng dụng trên cùng máy yếu làm số lệch → ghi vào residual risk.
